# Monetization roadmap

## Now: monetization-ready Community foundation

- Keep all local engineering capabilities free and offline-capable.
- Produce deterministic, redacted JSON and Markdown run evidence.
- Offer paid setup, workflow design, and team-pilot services.
- Gather measured completion, intervention, validation, time, and provider-usage evidence.

Exit signal: several paid pilots can be delivered repeatedly with useful reports and known support effort.

## Next: hosted control-plane minimum

Only after pilot evidence supports it, build authentication, a narrow hosted API, server-side entitlements, append-only metering, and one paid capability. Select the capability from observed demand; do not start with a broad platform.

Exit signal: entitlement and metering reconciliation are reliable, Community remains independent, and the paid capability has active customers.

## Later

Team workspaces, managed credits, remote sandboxes, enterprise deployment, and marketplace work remain separately gated investments. Each requires a threat model, unit economics, operational ownership, and explicit product approval.

## Decision metrics

Use task completion, validation success, human interventions, rework, time to validated result, provider cost, support hours, conversion, retention, and gross margin. Estimates must be labelled; unavailable values must not become zero.
